# genealogy-research

**Agent Skill** для Claude Code: ведение генеалогического исследования **как графа
с доказательной базой**. Люди и родственные связи в YAML, у каждой связи своя
достоверность и свои источники, гипотезы отдельно от фактов, дословные копии
документов рядом с их пересказом.

Задача навыка — не «нарисовать древо», а сделать так, чтобы **данные не терялись,
не устаревали и не расходились**. Это три разных отказа, и защита от каждого своя.

Репозиторий: <https://github.com/Ivan-Klimenko/genealogy-research-skill>

## Установка

```sh
git clone https://github.com/Ivan-Klimenko/genealogy-research-skill.git \
          ~/.claude/skills/genealogy-research
```

Каталог должен называться именно `genealogy-research` — по нему Claude Code находит
навык. Если репозиторий уже склонирован в другое место, достаточно симлинка:

```sh
ln -s ~/path/to/genealogy-research-skill ~/.claude/skills/genealogy-research
```

⚠️ Навыки обнаруживаются **при старте сессии**: после установки Claude Code нужно
перезапустить. Проверить, что подхватился, — командой `/genealogy-research`.

**Требуется** Python 3 с `pyyaml`, больше ничего.

Навык **не хранит данных**. Проект ищется по ближайшему каталогу с
`data/family_graph.yaml` выше текущего либо по переменной `GENEALOGY_PROJECT`,
поэтому скрипты запускают из корня проекта:

```sh
cd <ваш проект с data/>
python ~/.claude/skills/genealogy-research/scripts/validate.py --fix-counters --status
python ~/.claude/skills/genealogy-research/scripts/generate_tree.py
```

Первая команда сверяет данные, чинит счётчики и перезаписывает `STATUS.md` — файл,
который отвечает на вопрос «где мы и что дальше» и **вычисляется**, поэтому не может
разойтись с данными. Вторая рисует `web/index.html` — самодостаточную страницу
без внешних зависимостей, которую можно положить на любой хостинг и дать ссылку родне.

## Начать с нуля

Своих данных навык не приносит, но и пустой каталог ему годится: заведите
`data/family_graph.yaml` с одним человеком — собой, — и попросите агента
подключить навык. Минимальный рабочий пример лежит в `tests/fixtures/minimal/`.

## Состав

| Файл | Что внутри |
|---|---|
| `SKILL.md` | принципы, рабочий цикл, **семнадцать** правил доказательства родства, когда разворачивать параллельный наряд |
| `references/METHODOLOGY.md` | канон правил с разборами и примерами ошибок |
| `references/DATA-MODEL.md` | схема данных и что именно проверяет валидатор |
| `references/HANDOFF.md` | протокол параллельных веток, готовый промпт ветки-аудитора, схема `proposal.yaml` |
| `references/ARCHIVE-APIS.md` | обходы SPA-интерфейсов архивов и генеалогических баз — с границами каждого |
| `scripts/validate.py` | валидация целостности + генерация витрины состояния `STATUS.md` |
| `scripts/audit.py` | четырнадцать признаков, которые **читают тексты** и сверяют их с графом |
| `scripts/generate_tree.py` | отрисовка древа в HTML: раскладка Рейнгольда—Тилфорда, снимки документов, каскад допущений |
| `scripts/edit_prose.py` | библиотека правки прозы в YAML — знает, где ломается наивная регулярка |
| `scripts/build_scans.py` | веб-версии сканов: 2200 px для чтения, 400 px для плитки |
| `scripts/merge_handoff.py` | механика сведения отчётов параллельных веток |
| `scripts/yandex_*.py` | сплошная выкачка расшифровок и оригиналов сканов Яндекс-Архива |
| `tests/run_tests.py` | переносимость на минимальном проекте + регрессия по четырём главным ошибкам |
| `research_notes.md` | дневник разработки самого навыка |

⚠️ **`validate.py` и `audit.py` делают разное.** Первый проверяет **целостность** —
существуют ли ссылки, сходятся ли типы; всё, что он находит, обязано быть нулём.
Второй проверяет **соответствие утверждений основаниям** — говорит ли документ то,
что мы на него сослались. Его признаки нулём быть не обязаны, и гонять его надо
после каждой **перестройки** графа: перестройка меняет данные сама, а тексты под
ними не меняет никто.

## Идеи, ради которых это существует

**Достоверность живёт на связи, а не на человеке.** «Мы правильно опознали этого
человека» и «мы уверены, что он сын вот этого» — разные утверждения. Разделив их,
можно выразить множественные браки, боковые ветки и двух конкурирующих кандидатов
в отцы, не ломая модель.

**Существование, отождествление и родство — три разных утверждения.** «Прадед точно
был — его имя в отчестве деда» и «вот эта запись о нём» проверяются по-разному
и рушатся порознь. Пока они жили в одном поле, сказать «человек был, но запись,
может, не его» было нечем.

**Ссылка на документ — не id, а утверждение о роли.** «Документ назвал обоих вместе»
и «мы свели их по отчеству» — разные вещи, и подтверждённым родство делает только
первое. Пока роль не записывалась, цепочка из отчеств однофамильцев одной деревни
три месяца держала верхушку линии перевёрнутой. Теперь это ошибка валидатора,
и на неё есть тест.

**Производное не хранят руками.** Счётчики, видимость узла на полотне, поколения,
витрина состояния — всё, что выводимо, вычисляется. Записанное руками производное
ржавеет молча, и это проверено дорого трижды. ⚠️ Худший случай — тот, где вычислить
нельзя: подпись под карточкой («прадед», «брат прапрадеда») выводится из графа так же
строго, но написана словами. При перестройке поколения пересчитались сами, роли
промолчали — и девять человек сутки называли родство, которого в графе нет.

**Отрицательный результат — такой же результат.** «Не нашли поиском» и «прочли все
398 разворотов» — утверждения разной силы, и записывать надо оба, с указанием метода
и объёма. Отклонённые гипотезы не удаляются: они ограничивают пространство поиска.

**Найденное — ещё не внесённое.** Документ бывает скачан в оригинале, прочитан глазами,
разобран в гипотезе на пять абзацев — и не значиться ни в одном ребре, пока это ребро
стоит слабым. Реестр источников и граф связей расходятся молча, и валидатор теперь
показывает такие документы отдельно.

## Происхождение

Навык вырос из исследования одной семьи, которое ведётся с июля 2026 года и сейчас
держит 115 человек, 162 связи, 327 источников и 186 гипотез в семи фамильных линиях
на девяти поколениях. Все правила и предостережения здесь — не теория: за каждым стоит
ошибка, которая была допущена и стоила работы.

Данные той семьи в этот репозиторий не входят и не входили.
